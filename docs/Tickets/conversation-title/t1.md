## Parent

#34（对话命名 — AI 自动命名 + 手动改名，Workflow H）

## What to build

后端端到端：用户聊完一轮后，会话标题自动由 LLM 生成并写回——侧边栏数据源（conversations 列表）里能看到可辨认的标题；用户通过改名端点改过的标题永久生效、AI 永不覆盖；命名失败静默保持默认。命名逻辑全部收口在 ConversationManager 的一个可注入假 LLM 的方法里，WS 聊天处理器与 conversations API 只做接线。

核心规则（spec #34）：**title ≠ 默认值 → 跳过命名**。无数据库迁移，不新增列。

## Acceptance criteria

- [ ] ConversationManager 新增命名方法（如 `ensure_title`）：查 title → 等于默认值才继续 → 取首条用户消息 + 首条 AI 回复（各自截断）→ `chat_sync(max_tokens≈50, temperature=0.3)` 生成 ≤12 字标题 → trim/去引号后写回；`llm_service` 构造注入
- [ ] WS 聊天流 `done` 后起后台任务调用命名方法；`done` 带 `proactive` / `daily_greeting` 标记的不触发；同一会话 in-flight 去重（同时只一个命名任务）
- [ ] 重试：复用 `retry()`，max_retries=2、base 0.5s；彻底失败静默保持默认，不向客户端发事件；空结果同样保持默认
- [ ] 不做启动批量回填（老会话懒补：下次对话按同一规则补命名）
- [ ] 新增 `PUT /api/conversations/{id}`（body `{"title": "..."}`）：成功返回更新后的会话对象；空/全空白拒绝；会话不存在返回 404
- [ ] `test_conversation_title.py` 全绿：title==默认值才生成 / 已命名跳过（含用户改名后不再覆盖）/ LLM 失败重试后保持默认 / 空结果保持默认 / PUT 往返 + 拒绝 + 404（假 chat_sync + 内存 SQLite + TestClient，参照 `test_llm_retry.py` 与 `test_tool_runtime.py` 模式）
- [ ] 现有回归不破（`test_llm_retry.py`、agent 相关测试）
