# 09 — 并发调度器重写（纯逻辑）

**What to build:** 把群轮调度从「串行轮流」换成**全员起跑 + 事件唤醒的有界并发**：用户消息让所有成员
**同时开始一次思考**；此后每有一条新消息落库，就**唤醒每个「空闲且未用满 K」的成员**再思考一轮；
一次思考最多产出一条消息；全体用满 K 或无人再产出即**收敛**。

**Blocked by:** #08（同一文件的续说移除先落地，避免两处改动互相掩盖）

**Status:** ready-for-agent

**参考:** `docs/specs/group-chat.md`（群轮编排（并发 — ADR-0009））、`docs/adr/0009-concurrent-group-turns.md`

**关键语义（逐条都是验收对象）：**

- **全员起跑**：用户消息到达 → 所有成员同时开始思考（各自的独立生成），谁先想好谁先说。
- **事件唤醒**：每条新消息落库后，唤醒每个「空闲且未用满 K」的成员。
- **在途永不取消**：正在生成的成员先说完这一轮；"把在它思考期间落库的新消息注入给它"不需要新机制——
  每次思考都重读整段对话，注入是自然结果。
- **一次思考最多一条消息**；`<silent>` = 不产消息（不落库、不推送）但**仍消耗一轮**。
- **两道上限**（每个用户轮）：每成员最多 **K** 次思考（**N≤4 → 3；N>4 → 2**）；全局角色消息最多 **M = 9**。
- **额度预留**：发起一次思考**前**先检查消息余额，没余额就不发起——**绝不 generate-then-drop**。
- **收敛**：全体用满 K，或没有任何成员再产出消息且没有在途生成 → 整群静默。
- **新用户消息 = 全新的用户轮**：K 与 M **重置** + 唤醒全员。
- **保持纯逻辑**：注入「跑一个成员一轮」的可调用对象；并发用可注入的任务工厂，测试可等待。

## Checklist

- [ ] 调度器实现：起跑 / 唤醒 / K 按人数分档 / M 封顶 / 额度预留 / 收敛 / 在途不打断 / 新用户轮重置
- [ ] 跳过（`<silent>`）不产消息但仍计一轮
- [ ] 测试（假对象 + 可控并发原语）：
  - [ ] 用户消息 → 全员同时起跑并发生成
  - [ ] 新消息落库 → 唤醒空闲成员（已用满 K 的不再被唤醒）
  - [ ] 每成员恰好 ≤ K 次思考（含 N≤4 / N>4 两种分档）
  - [ ] 全局消息恰好 ≤ M；余额不足时**不再发起**新思考（不出现 generate-then-drop）
  - [ ] 全员沉默 → 收敛；全员用满 K → 收敛
  - [ ] 用户插话（新用户轮）→ K/M 重置、全员被唤醒
  - [ ] 在途生成不被取消
- [ ] 全量回归：`python -m pytest tests/ -v`
