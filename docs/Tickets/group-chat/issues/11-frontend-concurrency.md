# 11 — 前端并发渲染

**What to build:** 群聊界面支持**多个角色同时生成**（多个「正在输入」指示，而不是单一"正在回应"）；
收到的消息按**序号**稳定排序渲染，不因到达顺序错位；事件处理与后端新协议对齐。

**Blocked by:** #10（驱动与事件协议）

**Status:** ready-for-agent

**参考:** `docs/specs/group-chat.md`（群轮编排（并发））、`docs/adr/0009-concurrent-group-turns.md`

**关键语义：**

- 并发下**到达顺序不等于发言顺序**：渲染与追加一律以消息自带的**序号**为准。
- 多个成员可以同时在生成 → 界面要能同时显示多个"正在输入"，且各自独立收尾。
- 后端 `turn_end` / `done` 语义已变，前端不能再按"一轮一收"来处理（避免提前收掉"正在输入"）。
- 群聊仍**不触发 TTS**；1:1 界面不受影响。

## Checklist

- [ ] 支持多个"正在输入"指示（按角色区分，各自独立出现与消失）
- [ ] 收到的消息按序号排序渲染（同秒到达不错位）
- [ ] 事件处理与后端新协议对齐（`turn_end` / `done` / `group_message`）
- [ ] 手工验收：3 人群发一句 → 多人**同时**开始思考、消息按真实发言顺序排列、无错位或提前收起
- [ ] 1:1 界面与聊天 WebSocket 行为不受影响
