# 08 — 停用「继续说」（最小代价第一步）

**What to build:** 群轮里**每个成员每轮只生成一条消息**，「继续说」不再被调用。**只改调用点**——
生成函数的签名、`user_nudge`（DeepSeek 思考模式 400 的修复）、`<silent>` 跳过语义、落库前置
**全部不动**，好让这一步如果出问题，能**确定是"停用续说"造成的**，而不是并发重写。

**Blocked by:** None — 可直接开始。

**Status:** ready-for-agent

**参考:** `docs/adr/0009-concurrent-group-turns.md`（Consequences：续说退场的两步走）

**关键语义：**

- **`user_nudge` 必须保留**：它不是为续说存在的，是「带 tools 的请求不能以 assistant 结尾」的 400 修复，
  群聊**每一轮**都要用它收尾。
- 续说的提示词与 `is_continuation` 形参**先留着**（成为不可达分支）——死代码清理留给后续票，
  不要在这一步和并发重写混在一起。
- 依赖续说的测试改成「每成员一条」或删除：**这一步红了就是停用续说造成的**，可归因。
- 不改变其余任何行为：跳过仍不落库、消息仍由驱动落库并推送。

## Checklist

- [ ] 编排器里每个成员每用户轮只调用一次生成（去掉续说循环）
- [ ] `is_continuation=True` 成为不可达分支（签名与提示词暂留）
- [ ] 调整依赖续说的测试到新语义
- [ ] 全量回归通过：`python -m pytest tests/ -v`
