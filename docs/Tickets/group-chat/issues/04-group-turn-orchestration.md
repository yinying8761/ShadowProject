# 04 — 群轮编排 + WS 接线

**What to build:** 群聊的对话引擎——用户在群里发言后，成员**按顺序依次**决定「是否回应 / 是否继续说」，
可跳过；每个「用户轮」有**链预算**封顶；用户插话**不打断在途回复**、本轮收尾后成为**新轮**；
群对话**不触发**每日问候与主动说话。做完后后端已能完整跑通群聊。

**Blocked by:** #03（需要群 / 群对话与成员顺序）

**Status:** ready-for-agent

**参考:** `docs/specs/group-chat.md`（Phase 2 · 群轮编排）

**关键语义：**

- **串行**：一次只跑一个角色的一轮（一个 LLM 流），**永不并行**；顺序 = 成员 `position`。
- **三种输出**：跳过（提示词约定「无话可说时只输出 `<silent>`」，编排器识别后**丢弃**，不落库不推送）／
  一条消息（落库 `speaker_id` = 该角色并推送）／继续说（同一角色再生成一条，仍计入链预算）。
- **链预算**：每个「用户轮」角色消息总量上限 **6**（常量、可配）。到顶 → 整群静默；**全体跳过** → 本轮静默结束。
- **插话语义**：在途时用户又发消息 → 不打断；当前角色本轮收尾后**旧轮立即收束**（剩余成员不再就旧消息发言），
  队列中的用户消息**合并为一个新轮**（预算重置）接力；旧消息仍在历史中。
- 每角色上下文 = 完整群记录（时间戳格式）+ 该角色人设 + 该角色记忆 + **全量工具**（审批照常，归属该角色）。
- 群对话**不启动**主动陪伴会话、**不响应**每日问候。

## Checklist

- [ ] 跳过标记（`<silent>`）识别与丢弃
- [ ] 链预算 6 封顶 + 全体跳过静默
- [ ] 插话队列 → 新轮（合并、预算重置、在途不打断、旧轮收束）

- [ ] 每条角色消息落库 `speaker_id`
- [ ] 测试：编排器单测（顺序 / 跳过 / 预算 / 插话新轮 / 全跳过静默）+ WS 集成（后端跑通群聊）
