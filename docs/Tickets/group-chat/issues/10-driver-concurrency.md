# 10 — 驱动改写（WS 并发 + 唤醒 + 审批串行）

**What to build:** 群对话的驱动从「一次一串」改为**并发**：一条对话里可以有多个生成同时在途且互不阻塞；
消息一落库就**唤醒空闲成员**并推送 `group_message`（带序号）；**工具审批同一时刻只放行一条**，其余排队；
用户消息按「全新的用户轮」处理（入队 → 唤醒全员、额度重置）。做完后后端就是并发群聊。

**Blocked by:** #07（顺序确定性）、#09（调度器 API）

**Status:** ready-for-agent

**参考:** `docs/specs/group-chat.md`（群轮编排（并发））、`docs/adr/0009-concurrent-group-turns.md`

**关键语义：**

- 去掉「一个会话同一时刻只有一串群轮」的串行约束：并发生成由调度器记账（K/M），驱动只负责在途管理。
- **落库先于推送**，推送用落库后的文本；每条 `group_message` 带**序号**，前端据此排序。
- **用户消息落库先于任何成员读历史**这条契约在并发下仍要成立（现有的"结清落库"思路继续用）。
- **审批串行化**：同一对话内同一时刻只让一个审批请求出现在用户面前，其余排队（群聊工具全量，
  `write_file`/`see_screen` 仍需审批）。
- 群对话依旧**不启动主动陪伴、不响应每日问候**。
- 事件协议随并发调整：`turn_end{pending}` / `done{group}` 的语义在并发下要重新定义（或移除），
  并与前端对齐。

## Checklist

- [ ] 驱动支持多个在途生成（不再"每会话一个 turn task"）
- [ ] 新消息落库 → 唤醒空闲成员 → 触发新的思考
- [ ] 用户消息按新用户轮处理（入队、唤醒全员、额度重置）
- [ ] 审批串行化（同时只放行一条，其余排队；超时语义不变）
- [ ] `group_message` 携带序号；`turn_end` / `done` 语义重新定义并与前端对齐
- [ ] 测试（WS 集成 + 内存 SQLite）：并发生成、唤醒接力、审批排队、用户插话重置 K/M、消息序号正确
- [ ] 全量回归：`python -m pytest tests/ -v`
