# 01 — 后端：on_retry 回调 + LLM/Agent 透传 + llm_retry WS 事件

**What to build:** 聊天链路在流建立期间遇到瞬态错误（连接失败/超时/429/5xx）时，客户端通过
WebSocket 实时收到 `{"type":"llm_retry", attempt, max_retries}`，知道服务端正在退避重试；
重试全部失败照旧抛错（现有 `error` 事件兜底）。主动陪伴 / 每日问候链路不传回调，天然不受影响。

**Blocked by:** None — 可直接开始。

**Issue:** #38

**Status:** ready-for-agent

**关键语义：**

- `on_retry(attempt, max_retries, exc)`：每次实际退避重试前调用，`attempt` 为**即将进行的第几次
  重试（1 起）**，方便前端直接渲染「正在重试 (n/5)」。成功、不可重试错误、重试耗尽均不调用
  （耗尽表现为最终抛出原异常，与现状一致）。
- 直通 `send_json` 而不进 Agent 事件流：回调发生在 generator 深处的 await 链内，无法从回调处
  yield；纯 UI 瞬态不值得扩事件管道。但 CONTEXT.md §5.1 仍登记 `llm_retry`（客户端可见事件）。
- 仅覆盖**流建立**与 `chat_sync` 的重试；流中途断开不重试、不回调（现状，partial_error 兜底）。
- 回调是同步函数；chat.py 里用 `asyncio.create_task(websocket.send_json(...))` 派发，不阻塞退避节拍。
