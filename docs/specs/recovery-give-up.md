# 失败后放弃：按工具记账 + 轮次耗尽收尾

> 日期：2026-11-09 | 状态：**待确认**（等用户拍板后拆票） | 关联：`docs/analysis/eval-triage-2026-11-06.md`、`docs/adr/0012-eval-layering.md`
>
> 来源：eval 全量 `25/33` → recovery 子集复跑 `1/7`（28 次调用 / 84,817 tokens）后的逐条归因。

## Problem Statement

agent 在工具失败之后**不会停手**：它把同一个调用重试到 `max_tool_rounds`（5）耗尽，然后在轮次用完时**返回空回答**。

实测证据（recovery 子集，7 条里 1 条通过）：

| 用例 | 注入故障 | 实际行为 | 结果 |
|---|---|---|---|
| R01 | `read_file=error` | `read_file` 调 **5 次**（中间只夹一次 `list_directory`） | tools/answer/budget 三连挂，**最终回答为空** |
| R03 | `research`/`fetch_url` 熔断 | 熔断后仍换工具硬试 | tools 挂 |
| R04 | `research`/`fetch_url` 报错 | `research` **4 次** + `fetch_url` 1 次 | tools/answer 挂 |
| R05 | `see_screen` 报错 | `see_screen` **3 次**（回答本身是好的，见下） | 仅 answer 挂（断言问题） |
| R06 | `read_file` 返回空 | 换着读 4 个文件，空结果吃到轮次耗尽 | tools/answer 挂 |
| **R07** | `fetch_url` 超时 | 超时 **2 次**后如实说明 | **通过** |

两个独立缺陷：

1. **不放弃**：失败后没有"这个工具不行了"的账本，于是把预算烧在同一个坑里。R07 证明模型不是不会——它在第 2 次超时后停了；缺的是**强制**它这么做。
2. **收尾缺失**：轮次耗尽时直接返回空。用户看到的是"什么都没说"，而不是"工具一直失败，我没拿到内容"。

还有一个**评测侧**的缺陷（不修它就无法衡量上面两件事是否修好）：`answer` 断言用关键词闭集（`未写入`/`没看成`），模型说的是同义句（「那我就不写了」「试了几次都没抓到画面」）→ **语义对、字面错**，与 S03 的 host 精确匹配**同源**。

## Solution

**产品侧两件（改主循环）：**

- **(a) 按工具记失败账本**：同一工具**连续失败 2 次**即禁止在本轮再调用；允许换 **1 次**替代工具；替代也失败 → **立即停止**，如实报告没拿到。
- **(b) 轮次耗尽也要收尾**：`max_tool_rounds` 用完时，必须产出一句总结（"工具一直失败/没拿到内容"），**不允许空回答**。

**评测侧一件：**

- **(d) 断言语义化**：断言只约束**可判定的性质**（是否带来源、是否说明未完成、是否停手），**不约束用词**；语义判断交给评分模型或人。先落 ADR-0012 补充条款，再改用例——否则改用例一定会退化成"逐例补关键词"。

## User Stories

1. 作为用户，角色查不到东西时应当**停下来告诉我**，而不是对着同一个失败的工具反复尝试、最后什么都不说。
2. 作为用户，工具连续失败后它应当**换个办法试一次**，而不是原地重试。
3. 作为用户，即使它试到没有回合可用，也应当**说一句"我没拿到"**，而不是留空。
4. 作为开发者，我想让"重试次数"成为**可观测的账本**（按工具记），这样"这个工具坏了"和"模型选错了工具"能分开归因。
5. 作为开发者，我想让评测断言**不因同义表达而假红**，否则任何分数都不可信。
6. 作为开发者，我想让改动只发生在主循环和断言规则里，不改 `ToolRuntime` 的错误信封、不改工具签名。

## Implementation Decisions

### (a) 失败账本的位置与语义

- **位置**：`core/agent.py` 的工具循环内（硬限制），**不是** prompt。理由：R01 的 `read_file`×5 是模型无视软提示的直接证据。
- **键**：工具名。**连续**失败计数——该工具任意一次成功即将计数清零。
- **什么算失败**：`ToolRuntime` 返回的错误信封（`{"error": ...}`，含超时、熔断、schema 失败）。
- **什么不算失败**：**用户拒绝审批**不是工具故障——它应当让该工具在本轮**直接停用**（不重试），并在收尾话术里说明"没有执行"，但不应计入"工具坏了"的账本。
- **阈值 N=2**：`max_tool_rounds=5` 是硬上限，N=3 会让"两次重试 + 一次替代"吃满全部回合，没有余量收尾。N=2 给"换一次替代"和"收尾"各留空间。
- **替代**：同一轮内允许换 **1 个**不同工具；替代失败 → 立即停机。
- **不改变**：`max_tool_rounds` 仍为 5；预算/熔断/重试的既有语义不动。

### (b) 轮次耗尽的收尾

- 触发：`max_tool_rounds` 用尽且没有产生最终回答。
- 行为：发一次**不带工具**的收尾请求，要求用一句话说明（例如"工具一直失败，我没拿到内容"）。
- **兜底**：若这次收尾仍返回空（模型/网络问题），由代码写出一句固定文案，**绝不留空**。
- 收尾回答**不写入工具调用**，不计入工具账本。

### (d) 断言规则（先写 ADR，再改用例）

- **ADR-0012 补充条款**：断言只约束可判定的性质——`是否有来源 URL`、`是否说明未完成`、`是否停止调用`、`调用次数上界`；**不约束"必须出现某个词"**。
- 关键词只允许用于**硬事实**：URL 是否存在、数字是否出现、是否包含 `<silent>` 之类的**协议标记**。
- 语义类判断（"说清了没做成"）交给评分模型或人工，不交给字符串表。
- 迁移顺序：**先**落 ADR 条款 → 再改 S03/R02/R05 的断言 → 重跑，避免"逐例补关键词"。

## Testing Decisions

| Seam | 形态 | 测什么 |
|---|---|---|
| **S1 账本** | 纯逻辑 + 注入的假 runtime | 连续失败 2 次即禁调；成功即清零；禁止后换 1 次替代；替代失败即停；拒绝审批不计入但工具停用 |
| **S2 收尾** | 假模型（返回空） | 轮次耗尽时必定产出非空回答；模型返回空时走固定文案 |
| **S3 行为回归** | eval recovery 子集 | R01/R03/R04/R06 转绿；R07 保持绿 |
| **S4 断言规则** | 单测 | S03/R02/R05 用语义断言可通过；同义表达不再假红 |

- 目标（不是承诺）：recovery 子集从 **1/7 → ≥6/7**（R02/R05 靠 (d)，其余靠 (a)(b)）。
- 基线纪律：**(d) 落地前，`25/33` 不得作为质量分数**，只能作为问题清单。

## Out of Scope

- 提高 `max_tool_rounds`（这是治标，且违背成本上界）。
- 把"要不要重试"完全交给模型（已证明会被无视）。
- 引入 LLM-as-judge 做全自动评分（(d) 允许局部使用，全面改造另开）。
- 修改 `ToolRuntime` 的错误信封或工具签名。
- 其他类别的失败（T03 的回合耗尽、`--group` 挂起）另案。

## Further Notes

- **为什么不合并 (a)(b)**：R01 的"5 轮耗尽后回答为空"说明即使有了账本，也必须保证**停下来之后要说话**。两件事独立。
- **R07 是正面样例**：两次超时后如实说明即通过——可以直接当收尾话术的参照。
- **成本**：账本减少无效重试，实际是**省钱**的；收尾最多多 1 次调用。
- **分工建议**：(a)(b) 主循环改动 → 二号实施者；(d) 先 ADR 补充条款再改断言 → 审查者。
